<feature>
  <name>Multi-Outcome Arbitrage Detector</name>
  <files>src/detectors/multi-outcome-arb.ts, tests/multi-outcome-arb.test.ts</files>
  <behavior>
Detect multi-outcome arbitrage opportunities where buying/selling all outcomes yields guaranteed profit:

Arbitrage patterns:

1. Buy all outcomes (prices sum < 100%):
   - Example: 3 outcomes at 30%, 25%, 40% (sum=95%)
   - Buy $100 of each → spend $95 total
   - One outcome wins → payout $100
   - Guaranteed profit: $5 (5% edge)

2. Sell all outcomes (prices sum > 100%):
   - Example: 4 outcomes at 30%, 28%, 26%, 20% (sum=104%)
   - Sell $100 of each → collect $104 total
   - One outcome wins → payout $100
   - Guaranteed profit: $4 (4% edge)

Input: Market with multiple outcomes and their ask/bid prices
Output: ArbOpportunity[] with { market, type, edgeSize, capitalRequired, expectedProfit }

Edge size calculation:
- Buy arb: 100 - sum(ask_prices)
- Sell arb: sum(bid_prices) - 100
- Minimum threshold: 2% (to account for 2% fees on Polymarket)

Fee adjustment:
- Polymarket: ~2% fees per trade
- For N outcomes, fees = N * 2%
- Net edge = gross_edge - fee_percent
- Only flag if net_edge > 0.5% (safety margin)

Liquidity validation:
- Check order book depth for ALL outcomes
- Capital required: $500 min per outcome (based on user constraint)
- If any outcome lacks liquidity, skip opportunity

Test cases:
- 3 outcomes sum=95% with >$500 liquidity each: flag buy arb
- 4 outcomes sum=106% with >$500 liquidity each: flag sell arb
- 3 outcomes sum=98% but fees=6% (3*2%): skip (net edge negative)
- 5 outcomes sum=93% but one outcome has only $200 liquidity: skip
- Binary market (2 outcomes): handled by correlated detector (skip)
- Edge case: Market with 10+ outcomes → validate all have liquidity
- Edge case: Prices change mid-calculation → use snapshot timestamp

Confidence scoring:
- 0.9-1.0: High edge (>3% net) with deep liquidity
- 0.7-0.9: Moderate edge (1-3% net)
- <0.7: Skip (too close to fees)
  </behavior>
